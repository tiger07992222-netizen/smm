# Пайплайн SMM-бота Scores24

Актуально на 23 сентября 2026. Это текущее описание кода, не исторический отчёт.

Бот сам собирает четыре рубрики в день (матчи дня, экспресс, ставка дня, тренд), проверяет факты, публикует в Telegram и после матча дописывает ✅/❌. Человек нужен, только если валидатор зарубил пост или надо добавить канал.

Нейронка **не** ходит в Scores24, **не** выбирает матчи, **не** считает кэф и **не** публикует. Она пишет только подводку и промо на locale канала. Переводчика нет: каждый канал генерируется нативно.

---

## 1. Что крутится в проде

Один процесс: `python -m smm.main run` ([`smm/main.py`](smm/main.py)).

Внутри три вещи сразу:

1. **Админ-бот** `@scores24_smm_bot` — [`smm/bot.py`](smm/bot.py).
2. **Планировщик** (APScheduler) в том же файле.
3. Опционально HTTP `/ingest`, если задан `INGEST_TOKEN`.

Расписание (время канала `scores24` — Москва, остальные — свои TZ):

| Когда | Что | Код |
|---|---|---|
| 09:30 | Утренняя генерация всех enabled-каналов | `job_morning` → `job_generate` → граф `generate` |
| каждую минуту | Подхватить JSON + опубликовать due-слоты | `job_publish_tick` |
| каждые 10 минут | Дописать результат матча | `job_settle` |

Слоты публикации живут в yaml канала: 10:00 / 11:00 / 14:00 / 17:00. Отдельные cron на каждый слот **убраны** — в `:00` пост уходил дважды. Публикацию догоняет минутный tick.

Ручной вход: `/generate` в боте или `python -m smm.main generate --channel scores24 --force`.

## 2. Карта системы одним взглядом

```
канал yaml ──► morning (на каждый predictions_smm)
                               │
                    fetch_channel (API lang/TZ канала → picks)
                               │
                    rubric_graph × N
                      select_pick (kickoff/слот в TZ канала)
                      copy_llm (intro на locale)
                      validate ⇄ repair → adapt | escalate
                               │
                    publish (слот + канал привязан)
                               │
                    settle (счёт → правка сообщения)
```

Граф: [`smm/agent/graph.py`](smm/agent/graph.py).  
Узлы: [`smm/agent/nodes.py`](smm/agent/nodes.py).  
Стартовое состояние: [`smm/agent/bootstrap.py`](smm/agent/bootstrap.py).

Живая работа (HTTP, SQLite, Telegram) не в графе, а в сервисах: [`smm/data_sources.py`](smm/data_sources.py), [`smm/pipeline.py`](smm/pipeline.py), [`smm/publisher.py`](smm/publisher.py), [`smm/settler.py`](smm/settler.py).

## 3. Канал — единица destinации

Новый язык = новый yaml, граф не трогаем. Шаблон: [`config/channels/_template.yaml`](config/channels/_template.yaml).

Сейчас:

| Файл | slug | locale | TZ |
|---|---|---|---|
| [`config/channels/scores24.yaml`](config/channels/scores24.yaml) | `scores24` | ru | Europe/Moscow |
| [`config/channels/scores24-en.yaml`](config/channels/scores24-en.yaml) | `scores24-en` | en | Europe/London |
| [`config/channels/scores24-pt.yaml`](config/channels/scores24-pt.yaml) | `scores24-pt` | pt | Europe/Lisbon |
| [`config/channels/scores24-es.yaml`](config/channels/scores24-es.yaml) | `scores24-es` | es | Europe/Madrid |
| [`config/channels/scores24-de.yaml`](config/channels/scores24-de.yaml) | `scores24-de` | de | Europe/Berlin |

Реестр: [`smm/channels.py`](smm/channels.py). Yaml + SQLite: telegram id канала, enabled, иногда `config_json`. `lang` и `timezone_offset` подставляются из locale/TZ, если не заданы явно.

Общие правила дня — [`config/default.yaml`](config/default.yaml):

- кэф не фильтруем: берём первый пик с эндпоинта (бэкенд уже отсортировал);
- **min_kickoff** (местное время канала): экспресс ≥ 12:00, ставка ≥ 15:00, тренд ≥ 18:00;
- ссылки «Для России / за рубежом» — подписи локализует [`smm/i18n_links.py`](smm/i18n_links.py), URL те же.

`telegram_chat_id` в yaml не пишут: канал привязывают, переслав боту пост из него. Пока id пустой, в публичный канал ничего не уйдёт — только превью админам.

## 4. Пайплайн от начала до конца

Дальше — один утренний прогон одного канала. То же самое делает `/generate`.

### Шаг 0. Процесс уже жив

[`smm/main.py`](smm/main.py) поднял polling и cron. В 09:30 `job_generate` зовёт `run(..., intent=generate)` → [`run_morning`](smm/agent/morning.py): для каждого enabled `predictions_smm` канала — свой `fetch_channel` (lang/TZ) и свой `invoke_rubric` × N. Переводчик/pack-граф на утро не вызывается. RU в логах идёт первым.

### Шаг 1. Bootstrap — что кладётся в state

[`smm/agent/bootstrap.py`](smm/agent/bootstrap.py) читает канал и кладёт в [`AgentState`](smm/agent/state.py):

- `intent=generate`, slug, locale, timezone, день;
- `content_profile`, `data_source`, список рубрик;
- готовые system-промпты copywriter / validator / repair через [`smm/prompts.py`](smm/prompts.py).

Тексты промптов — [`smm/prompts/templates/`](smm/prompts/templates/). Склеиваются так:

- копирайтер: `copywriter_base.md` + `copywriter_{express|bet|trend}.md` + `scores24.md` + `meta.md`;
- валидатор: `validator.md` + бренд + `meta.md`;
`meta.md` говорит модели: пиши на языке `{locale}`.

### Шаг 2. fetch_channel — факты на диск под язык/TZ канала

Утро зовёт [`fetch_channel`](smm/agent/fetch_ru.py) → [`fetch_for_channel`](smm/data_sources.py) с params канала (`lang`, `timezone_offset`).

Kind канала `scores24_top` → [`fetch_and_ingest_for_channel`](smm/scores24_api.py) + добор рубрик.

Что реально дергается (секрет `X-Internal-Request`, LLM его не видит):

| Зачем | Endpoint | Модуль |
|---|---|---|
| Сырые топ-прогнозы (кандидаты) | `GET /rapi/predictions/top?lang=…` | [`smm/scores24_api.py`](smm/scores24_api.py) |
| Матчи дня | `GET /rapi/predictions/sports` по футболу, потом теннис/баскетбол/хоккей/волейбол | [`smm/top_matches.py`](smm/top_matches.py) |
| Экспресс | `GET /rapi/localized/express?section=default` | [`smm/express_coupon.py`](smm/express_coupon.py) |
| Ставка дня | тот же express, `section=betoftheday` | там же |
| Тренд | `GET /rapi/localized/trends/list` | [`smm/trends_main.py`](smm/trends_main.py) |

После GET:

1. Raw JSON кладётся в `data/api_cache/` (без секрета).
2. Ответ парсится в список **Pick**.
3. [`postprocess_day_picks`](smm/scores24_api.py) подменяет экспресс/ставку/тренд купонами API, выкидывает женский футбол ([`smm/womens_football.py`](smm/womens_football.py)), иногда обогащает статистику через старый [`smm/trends_fetch.py`](smm/trends_fetch.py).
4. Пики пишутся в `data/picks/{день}_{канал}.json` ([`smm/store.py`](smm/store.py)).

LLM сюда не ходит. Если API молчит, можно кинуть JSON в `data/incoming/` — [`smm/ingest.py`](smm/ingest.py).

Для `tick` / `settle` этот узел **не** дергает утренний API: только incoming-файлы.

### Шаг 3. select_pick — кого берём в слот

[`node_select_pick`](smm/agent/rubric/nodes/select_pick.py) + [`smm/selector.py`](smm/selector.py).

На каждую рубрику канала один пик из **пиков этого канала**. Код, не модель.

Фильтры по порядку:

1. Уже `published` / `settled` / `skipped` — не трогаем (если не `--force`).
2. Не тот тип, женский футбол, кибер в тренд — нет. Кэф не режем: порядок как в ответе API.
3. Матч не должен повториться в экспрессе, ставке и тренде одного дня **этого канала**.
4. Kickoff ещё не наступил (с буфером 5 минут) и не раньше слота публикации.
5. **min_kickoff в TZ канала:** экспресс ≥ 12:00, ставка ≥ 15:00, тренд ≥ 18:00 (`rubric_min_kickoff`).

Пример: ставка в 16:00 МСК ок для России; для Лондона это 14:00 — порог 15:00 не проходит, нужен другой матч из пиков EN-канала.

### Шаг 4. generate — сборка текста

[`node_generate`](smm/agent/nodes.py).

**Путь A — перевод.** Если в state есть `localize_from`, [`translate_draft`](smm/localize.py) одним запросом переводит уже собранный RU-пост (`translate.md`). Числа, URL, флаги, HTML-теги не меняет. Подписи ссылок подменяет [`smm/i18n_links.py`](smm/i18n_links.py). Каркас матча (вид спорта, «odds») должен уехать вместе с текстом.

**Путь B — сборка с нуля.** [`build_draft`](smm/pipeline.py) → [`render_post`](smm/copywriter.py):

1. LLM пишет JSON `{intro, closing, promo_text}` ([`_llm_intro`](smm/copywriter.py)). Прокси `OPENAI_PROXY`, иначе с прода в РФ будет 403.
2. Код собирает тело: флаги, линия, кэф, блок 💡 статистики. Для тренда факты режет LLM в `stat_groups` (`stat_groups.md`: head = тип ставки, tails = условия; без перевода — вход уже на locale). При сбое — regex (`group_trend_fact_blocks` → `format_trend_facts_display`).
3. В конец — promo + две geo-ссылки.
4. Баннер рисует [`smm/banner.py`](smm/banner.py) (Pillow / smm-banner-gen).

Если LLM три раза не выдала валидную копирайтерскую проверку (`_validate_llm_copy`) — черновик `needs_human` с пустым текстом.

Каркас **не** выдумывает кэфы и серии. Они уже в Pick.

### Шаг 5. validate — железо, не вкус

[`node_validate`](smm/agent/nodes.py) → [`validate`](smm/validator.py).

Железные проверки (`_iron_checks`):

- каждый `locked_fact` есть в тексте (с учётом группировки 💡 / «in N of» / «в N из»);
- нет чисел, которых не было во входе (дата, факты, ссылки);
- длина, живые URL;
- матч ещё не начался;
- тренд не содержит «Ставка дня» / Bet of the day, ставка — наоборот;
- алфавит roughly совпадает с locale (кириллица / латиница).

LLM-валидатор (`validator_use_llm`) по умолчанию **выключен**: gpt-4o-mini галлюцинировал запреты.

До 3 попыток. Между ними — repair.

### Шаг 6. repair

[`node_repair`](smm/agent/nodes.py):

1. Подтянуть актуальный кэф из кэша/API (`sync_pick_odds`).
2. Пересобрать тело.
3. Попросить LLM переписать intro/promo под список ошибок.

Снова validate. Если не вышло — escalate.

### Шаг 7. adapt или escalate

- **adapt** — статус `approved`, слот записан, draft в SQLite. Следующая рубрика или конец.
- **escalate** — `needs_human`, алерт админам с кнопками «смотреть / править». В канал само не уйдёт; tick раз в час напомнит, если слот уже прошёл.

После всех рубрик `job_generate` шлёт утреннюю сводку: какие посты собрались и во сколько слот ([`notify_morning_summary`](smm/pipeline.py)).

### Шаг 8. publish

Минутный tick: [`job_publish_tick`](smm/main.py) → граф `publish` → [`publish_due`](smm/pipeline.py).

Условия:

- статус `approved` (или `failed` на ретрае);
- `slot_at <= сейчас` по TZ канала;
- у канала есть `telegram_chat_id` и токен;
- матч ещё не стартовал ([`smm/kickoff_gate.py`](smm/kickoff_gate.py), буфер 5 минут);
- `message_id` ещё нет.

Шлёт [`smm/publisher.py`](smm/publisher.py): фото + caption, если влезает в 1024, иначе фото и текст отдельно. Лимит текста 4096.

Непривязанный канал (en/pt/es/de без chat id) публично не постит. Превью админам — `send_previews`.

### Шаг 9. settle

Каждые 10 минут граф `settle` → [`settle_due`](smm/pipeline.py) → [`smm/settler.py`](smm/settler.py) + [`smm/match_fetch.py`](smm/match_fetch.py).

После ожидаемого конца матча тянется счёт, каждая нога считается won/lost/void, в Telegram-пост дописываются ✅/❌, статус `settled`.

## 5. Сущности, которые стоит держать в голове

Описаны в [`smm/models.py`](smm/models.py).

**Leg** — один матч: команды, kickoff, линия, кэф, stat_text, флаги стран.

**Pick** — выбор на рубрику: тип (`express` / `bet` / `trend` / `top_matches`), ноги, общий кэф, `source` (сырые факты тренда и т.д.).

**Draft** — то, что увидит человек: `text`, `text_html`, баннер, `locked_facts`, статус, слот, `message_id`, `promo_text`, ссылки, вложенный Pick.

Статусы: `generated` → `approved` → `published` → `settled`. Развилки: `needs_human`, `skipped`, `failed`.

Диск: `data/picks/`, `data/api_cache/`, `data/smm.db` (черновики, каналы, ссылки, админы).

## 6. Два способа собрать день (и какой живой)

| Путь | Кто зовёт | Зачем |
|---|---|---|
| **Граф** `run(..., "generate")` | cron, `/generate`, `job_generate` | прод |
| **`generate_day`** в [`smm/pipeline.py`](smm/pipeline.py) | `preview`, тесты, fallback без токена | обход графа |

Логика почти скопирована (kickoff, localize, validate). Они уже расходятся по мелочам. Живой путь — граф. `generate_day` лучше сузить до тестов или удалить из CLI, чтобы не чинить одно и то же дважды.

## 7. Что устарело и что с этим делать

Ниже не «красиво бы», а конкретный хвост после месяцев правок.

### Можно удалить почти сразу

**Мёртвый код процесса**

- [`job_tick`](smm/main.py) и [`_slot_jobs`](smm/main.py) — нигде не вызываются. Слоты сознательно уехали в минутный tick.
- [`COPYWRITER_SYSTEM = ""`](smm/copywriter.py) — пустая заглушка.

**Старый слой промптов `smm/skills/`**

Живые промпты — [`smm/prompts/templates/`](smm/prompts/templates/).  
[`smm/skills/`](smm/skills/) (`copywriter.md`, `validator.md`, `top_matches.md`, …) читает только [`smm/skills/loader.py`](smm/skills/loader.py), а его — один тест в [`tests/test_core.py`](tests/test_core.py). Bootstrap ещё передаёт extra `top_matches` / `validator_top_matches`, но новый `build_system_prompt` эти имена **игнорирует**. Папка skills — труп. Либо удалить и поправить тест, либо честно снова подключить.

**Одноразовые скрипты**

В [`scripts/`](scripts/) десятки `_probe_*`, `_test_*`, `_list_*`, `_diag_*` — отладка API и черновиков. Плюс только что появившийся [`scripts/_gen_locales.py`](scripts/_gen_locales.py) (прогон en/pt/es/de). Для репозитория достаточно `deploy_*.sh`, `recover_prod.sh`, `check_bot.sh`. Остальное можно снести.

**Старые отчёты**

Эти файлы описывают мир «три поста, skills, generate_day как центр» и типы `express_football`:

- [`ОТЧЕТ_архитектура_пайплайна.md`](ОТЧЕТ_архитектура_пайплайна.md)
- [`ОТЧЕТ_экспресс_тренды.md`](ОТЧЕТ_экспресс_тренды.md)
- [`ОТЧЕТ_промпты.md`](ОТЧЕТ_промпты.md)
- [`ОТЧЕТ_валидатор.md`](ОТЧЕТ_валидатор.md) — частично устарел (вызов уже из графа, LLM-валидатор выключен)
- [`reports/llm_copy_samples_*.md`](reports/)

Этот файл — актуальная замена. Старые лучше не читать как инструкцию.

### Нужно адаптировать, не просто стереть

**1. Порядок генерации каналов**  
Сейчас yaml сортируется по имени: de/en/es/pt раньше `scores24`. Перевод с русского срабатывает, только если RU-пост уже лежит в базе (как сегодня с трендом). Иначе каждый язык собирается с нуля. В `job_generate` сначала `scores24`, потом остальные.

**2. `generate_day` vs граф**  
Дубль. Оставить граф каноном, из `preview` тоже звать `run(..., "generate")`.

**3. Типы `express_football` / `trend_tennis`**  
В yaml рубрики уже `express`, `bet`, `trend`, `top_matches`. Старые типы живы в [`smm/post_kinds.py`](smm/post_kinds.py), [`smm/pipeline.py`](smm/pipeline.py) (`POST_TYPES`, `TYPE_RU`), боте и куче тестов. `base_kind()` их понимает, но в проде они не создаются. Можно сузить, когда тесты перестанут на них опираться.

**4. `expand_football_bet_trend`**  
В [`smm/scores24_api.py`](smm/scores24_api.py) до сих пор делает запасные bet/trend из футбольных ног top. Основной источник ставки — `section=betoftheday`, тренда — `trends/list`. Функция — страховка. Имеет смысл проверить, выбирается ли она хоть раз; если нет — убрать, чтобы не плодить лишние пики.

**5. `trends_fetch.enrich_picks_with_trends`**  
Старый добор статистики. Тренд дня уже приходит с фактами из `/trends/list`. Обогащение ещё может помочь экспрессу/ставке. Если факты там свои — вызов лишний.

**6. Stub `table_tennis_stats`**  
Заготовка в [`smm/data_sources.py`](smm/data_sources.py) и `content_profile`. Граф честно уходит в `profile_unsupported`. Оставить как дырку под будущее или вычистить, чтобы не путать.

**7. README**  
[`README.md`](README.md) пишет «без ключа нейронки intro шаблонный, посты уйдут». Сейчас без успешного LLM `render_post` часто возвращает `None` → `needs_human`. И основной fetch уже не один `/predictions/top`.

**8. Немецкая починка после перевода**  
Если translate прошёл, а validate завернул, `repair` пересобирает тело из Pick. Факты пика остаются на языке API/RU — так в DE-тренде немецкий intro соседствовал с русским блоком статистики. Repair после localize должен либо снова переводить, либо не трогать уже переведённое тело.

**9. Лишнее число в EN**  
Валидатор ругал `27` в английском экспрессе/матчах дня. Скорее дырка `_allowed_numbers` (дата на английском, «September 23», обрезки URL), не плохой матч.

### Оставить как есть

- [`smm/trends_fetch.py`](smm/trends_fetch.py) — пока им пользуются postprocess и тесты.
- [`smm/http_ingest.py`](smm/http_ingest.py) — живой запасной вход.
- [`smm/tools/ops.py`](smm/tools/ops.py) — тонкая обёртка, её зовут узлы publish/settle.
- Каналы en/pt/es/de enabled: cron начнёт их собирать каждое утро. В публичный Telegram они не уйдут, пока нет `telegram_chat_id`. Сводки админам — да.

## 8. Как читать код в этом порядке

Не прыгать по репозиторию. Идти так:

1. [`smm/main.py`](smm/main.py) — вход, cron, CLI.
2. [`smm/agent/graph.py`](smm/agent/graph.py) — одна страница рёбер.
3. [`smm/agent/bootstrap.py`](smm/agent/bootstrap.py) — что в state.
4. [`smm/agent/nodes.py`](smm/agent/nodes.py) — что делает каждый узел.
5. От узла точечно:
   - fetch → [`smm/data_sources.py`](smm/data_sources.py) → api / express / trends / top_matches;
